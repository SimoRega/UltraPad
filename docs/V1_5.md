# UltraPad v1.5 — Google e ospite

La pagina iniziale offre «Accedi con Google», «Accedi con GitHub» e
«Continua senza account».

## Modalità ospite

Il primo accesso è vuoto: non vengono caricati documenti account o team.
Puoi creare file, importarli dal PC, usare gli editor TXT visuale/sorgente,
strumenti per formato, anteprime HTML/Markdown/LaTeX, rinominare ed eliminare.
I download sono disponibili dall’editor, anche con errori di storage.

Non viene creato un account anonimo Supabase. Non vengono inviate richieste
al database o al backend collaborativo; non sono disponibili «Salva nel DB»,
condivisione, cronologia server o workspace di team. Le copie restano nella
stessa scheda tramite sessionStorage fino alla sua chiusura: scaricale per
conservarle. Fino a 20 file e 1 MiB per file, soggetti alle quote browser.
Tornare al login non trasferisce automaticamente i documenti al database.

## Attivare Google per il progetto UltraPad

1. In Google Cloud / Google Auth Platform configura un progetto, Branding
   (nome UltraPad), Audience e i permessi `openid`, email e profile.
   Se l’app è in Testing aggiungi gli account da usare come test users.
2. In Clients crea un OAuth client ID di tipo **Web application**.
3. Authorized JavaScript origins:
   - `https://ultrapad-5q2.pages.dev`
   - `http://localhost:5173` se usi lo sviluppo locale.
4. Authorized redirect URIs:
   `https://iqlxqzfivunyudfaxjlr.supabase.co/auth/v1/callback`.
   È la callback Supabase, distinta dal redirect finale del frontend.
5. In Supabase → Authentication → Sign In / Providers → Google abilita il
   provider e inserisci Client ID e Client Secret creati da Google. Salva.
   Non inserire il secret in `.env.production` o nelle variabili `VITE_*`.
6. Supabase → Authentication → URL Configuration:
   Site URL `https://ultrapad-5q2.pages.dev`; Redirect URLs
   `https://ultrapad-5q2.pages.dev/` e, se necessario, `http://localhost:5173/`.
7. Dopo il deploy verifica consenso Google, ritorno al sito, profilo e logout
   con un account reale. I test locali usano fixture del servizio Auth.

Fonte ufficiale: https://supabase.com/docs/guides/auth/social-login/auth-google

## Aggiornamento

Nessuna migrazione SQL aggiuntiva. Configurazioni pubbliche della produzione
restano in `.env.production` e `apps/api/wrangler.jsonc`.

```powershell
pnpm.cmd install --frozen-lockfile
pnpm.cmd build:web
pnpm.cmd deploy:web
```

Il backend non cambia per questa release. Il codice non abilita da solo
Google nel servizio remoto: occorrono i passaggi account descritti sopra.
ADR 0007 documenta isolamento, conservazione e limiti della modalità ospite.

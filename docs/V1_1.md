# UltraPad v1.1

## Aggiornare una v1 funzionante su Windows

1. Ferma `pnpm dev` con Ctrl+C e aggiorna i sorgenti da GitHub. Se usi lo ZIP,
   conserva `.env` e `apps/api/.dev.vars` e sovrapponi i nuovi file.
2. Nel SQL Editor del tuo progetto Supabase esegui **solo**
   [`supabase/migrations/202610050004_v11.sql`](../supabase/migrations/202610050004_v11.sql).
   La migrazione è transazionale e aggiunge campi e funzioni; non elimina
   file, progetti, workspace o utenti. Non rieseguire 001–003 già applicate.
3. Dalla radice del progetto:

```powershell
pnpm.cmd install --frozen-lockfile
pnpm.cmd run doctor
pnpm.cmd dev
```

Il controllo opzionale `pnpm.cmd run doctor -- --api` richiede il backend
avviato: eseguilo in un secondo terminale. Apri http://localhost:5173/. Non occorre riconfigurare OAuth.
Per un'installazione nuova applica invece tutte le quattro migrazioni in ordine.

## Home e organizzazione

La home usa l'intera area disponibile, mantenendo la barra di navigazione.
Mostra fino a 100 file autorizzati più recenti, recuperati dal database con
RLS, e i progetti accessibili. Ricerca per nome file, progetto e tema.
“Aperti di recente” usa gli ID visitati da questo account in questo browser
(fino a 20), incrociati con i file autorizzati caricati. “Attività del team”
mostra file il cui ultimo autore noto è un altro utente, non il log completo
degli eventi. Aggiornamento automatico ogni 20 secondi mentre la home è aperta.

Assegna un tema da una scheda file o dal pulsante nel progetto. La precedenza
è: tema del file, tema del progetto, categoria del formato. I temi sono
metadati condivisi; modificarli richiede almeno il ruolo editor. Il raggruppamento
per formato non interpreta né invia il contenuto a servizi AI.
Le vecchie righe non hanno un autore storico ricostruito: il primo nuovo
cambiamento aggiorna l'indice; non vengono inventati eventi precedenti.

## File singoli e temporanei

“File singolo” crea atomicamente il file in un contenitore personale privato,
provisionato al primo utilizzo. Non serve prima creare workspace o progetti.
Usa gli stessi permessi, limiti, room Yjs, checkpoint e recupero dei file dei
progetti. Il contenitore personale non accetta inviti o altri membri.

“File temporaneo” funziona anche senza contattare il database. Il contenuto
resta in `sessionStorage`, separato per account, nella scheda corrente: resiste
al ricaricamento ma non è una copia durevole e termina con la chiusura della
scheda/sessione browser (il ripristino delle schede dipende dal browser).
Limite: 20 temporanei, 1 MiB ciascuno, entro la quota disponibile del browser.
Se lo storage non è disponibile compare un errore; scarica il testo dall'editor.
“Salva nel DB” crea un file singolo e ne inizializza il contenuto attraverso
il normale provider collaborativo. Attendi “salvato sul server”. Il temporaneo
originale resta disponibile fino alla sua eliminazione esplicita, anche se
la promozione fallisce o il nome è già usato. Nessun invio del testo temporaneo
al server finché non scegli di salvarlo.

## Aspetto e strumenti

Il pulsante “Aspetto” nella barra laterale apre temi bianco e nero, palette e
colore principale libero. La preferenza persiste in questo browser e vale
anche per Monaco; il testo dei pulsanti principali usa un contrasto adeguato
al colore selezionato. L'interfaccia usa superfici, bordi smussati e ombre leggere.

Ogni estensione supportata ha una barra dedicata. Le azioni modificano il
sorgente tramite Monaco, quindi partecipano a undo/redo e allo stesso Yjs.
Il ruolo viewer/commenter non può usare gli strumenti di scrittura.

| Formato | Strumenti principali |
| --- | --- |
| TXT e sconosciuti | Elenco, separatore, data |
| Markdown | Titolo, grassetto, corsivo, link, checklist, codice, tabella |
| JSON | Oggetto, array, proprietà, formatta e verifica sintassi |
| XML | Elemento, attributo, commento, CDATA, verifica sintassi |
| HTML | Pagina, titolo, link, immagine, sezione, formatta |
| CSS | Regola, flexbox, grid, media query, formatta |
| JavaScript / TypeScript | Funzioni, async / tipi e interfacce, formatta |
| Java / C# | Classe, metodo, main/Javadoc o proprietà/namespace |
| Python | Funzione, classe, main, docstring |
| TEX / BIB | Documento, sezioni, formule, citazioni / articolo e libro |

Formattazione disponibile nei linguaggi con formatter Monaco incorporato.
Verificare JSON/XML controlla la sintassi, non uno schema applicativo. Nessun
codice o HTML viene eseguito. LaTeX resta sorgente; Office/PDF, compilazione,
rich text e conversioni non sono introdotti da questa release.

## Verifica

Test automatici locali coprono SQL reale/PostgreSQL emulato con RLS,
contenitori personali, temi e indice attività; workerd/SQLite e protocollo;
browser con Monaco, temi, temporanei e strumenti. Le fixture Auth/DB dei test
browser non certificano le credenziali o la migrazione del progetto remoto.
La v1 è stata confermata funzionante dal proprietario; la migrazione v1.1
nel suo progetto deve essere applicata prima di provare le nuove funzioni.

Risultato locale: 48 test passati (13 unit/PostgreSQL, 14 integrazione,
3 setup, 18 browser), typecheck/lint e build/dry run passati.
